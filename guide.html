01

Ye platform hai kya, aur kaise chalta hai

Do minute ka context, taaki aage har cheez samajh aaye.

Ek folder, koi server nahi

Har diagram ek independent HTML file hai. index.html kholte hi sab kuch load ho jaata hai. file:// pe chalta hai - na Node chahiye, na Python, na internet.

Sab kuch generated hai, haath se nahi

Diagram ka data, code links, index aur code mirror sab tools/*.mjs scripts se bante hain. Isliye content kabhi diagram aur real code se drift nahi karta.

Diagram = ek idea

Har page sirf ek cheez sikhata hai: request path, proxy trap, transaction boundary, readiness probe. Ek page = ek mental model. Isliye 21 pages hain, ek bada page nahi.

Real code, real responses

Book Store project ka source page ke andar hi mirror hota hai, aur API responses ek baar live capture kiye gaye hain - N+1 ka 18 queries vs 1, transaction modes ka 201/409. Sab proof ke saath.

Sab kuch browser mein rehta hai

Quiz score, notes, progress - sab localStorage mein, sirf isi browser mein. Kuch upload nahi hota. Progress tab se ek click mein reset bhi ho jaata hai.

Offline bhi, print bhi

Theme toggle aur Print button dono kaam karte hain, isliye poori revision ek PDF mein export karke le sakte ho.

02

Pehla kadam - shuruaat kahan se karein

Order matter karta hai. Neeche ka sequence isliye banaya gaya hai kyunki aage wale diagrams pehle wale ke bina meaningful nahi lagte.

  1. index.html kholo, Home tab pe raho Upar stats dikhenge (21 diagrams, 196 nodes, 61 views...), neeche "Start here: the roadmap" card. Isi pe click karo.
  2. Roadmap diagram padho - 15 minute Spring_Boot_Roadmap.html chhe hisson mein poori journey dikhata hai. Abhi detail mein mat jaao, sirf "kaun sa topic kab aayega" wala map banao.
  3. Hub ke Tracks tab pe jao Chhe tracks hain: Foundations, How it works, Data and persistence, Security, Running it, Hardening. Har track ke andar diagrams sequence mein diye hain - upar se neeche jaao. Track ke saamne progress bar hai.
  4. Pehla real diagram: Request Path Browser se SQL tak ka poora safar. Yahi wo diagram hai jisse baaki sab samajh aana shuru hota hai. Node pe hover karo, passport padho.
  5. Har diagram ke baad Q dabao Quiz sirf usi diagram ke sawaal dikhata hai. Galat jawab ka explanation khud aata hai, plus "Walk through" aur source link - wahi se seedha code pe jump karo.
  6. N se note likho Jo cheez baar baar bhoolte ho, usi node pe note likh do. Notes progress ke saath browser mein save rehte hain - interview revision ke liye yahi kaam aayega.
Tip: Ek baar mein saare 21 diagrams mat kholo. Ek track khatam karo, quiz clear karo, tabhi agla track shuru karo. Warna information overload ho jaayega aur retention zero.

04

Diagram page ki anatomy

Koi bhi diagram kholo, interface hamesha same rahega. Ek baar samajh lo, 21on pages pe kaam aa jaayega.

Hover / Tab = semantic passport

Kisi bhi node ya relationship pe hover karo (ya keyboard se Tab se uspe focus lo) - ek card khulta hai jismein summary aur teen specific points hoti hain. Ye ratne wala content nahi, samajhne wala content hai.

Concept chips = sideways jump

Passport ke andar agar concept chips dikhein, matlab ye idea doosre diagrams mein bhi hai. Chip pe click karo - wahi concept us angle se khul jaata hai.

Code chips = seedha source

Passport mein jo file ka chip hota hai, wo us node ka real code dikhata hai - in-page viewer mein, naye tab mein nahi.

Guided views + Present mode

Har diagram mein 0-3 guided views hain. P dabao: baaki nodes dim ho jaate hain, sirf focus wale bright rehte hain, neeche narration aata hai. →, Space ya P se aage, ← se peeche.

Upar ki toolbar

Search, Walk through, Code lab, Quiz, Notes, Present, Terms, Debug, Interview, Hub - sab ek click door. Har button ke saath uska shortcut bhi likha hota hai.

Deep links

Koi page aise bhi khulta hai: ...html#node=query101 (specific node pe focus) ya ...html#view=quiz (turant quiz panel). Notes ya apne bookmarks mein aise links rakho.

Keyboard-first chalo: Mouse ki zaroorat hi nahi. Tab se node-to-node, Enter se detail, Esc se band. Screen reader users ke liye har node ka ARIA label bhi defined hai.

06

Code lab - theory ko actual code se jodo

Ye wo jagah hai jahan diagram "proof" mein badalta hai. Shortcut C.

Code lab panel (C)

Diagram ka overview, uske shared concepts, guided views, aur "Runnable code in Book Store" ki list - har file ke saath "in page" badge. Neeche Walk through aur captured response ke buttons.

Source viewer

Har code link ek hi page andar khulta hai: upar file ka role badge, path aur summary; uske neeche structure outline (class/method/field chips) jinpe click karke seedha line pe jump karo; phir poora file syntax highlighting ke saath; aur jo lines explained hain, unke saath unka explanation.

Walk through (walkthrough)

N+1 aur Transactions diagrams pe toolbar mein "Walk through" button hai. Har step mein source ke saath us waqt ka database query count ya transaction report side by side hota hai. Step by step dekho ki 1 query kaise 18 ban jaati hai.

Captured responses (evidence)

Ye screenshot nahi, ek baar live app chala kar capture kiye gaye real HTTP responses hain: join-fetch = 1 query aur payload byte-identical, mode=required / requires-new = 201, mode=poison = 409 rollback.

Dhyan do: Koi bhi code reference kabhi raw text dump nahi dikhata. Agar kisi file ka mirror missing ho, viewer khud batata hai ki kaunsi script chalani hai (node tools/build-code-viewer.mjs) - aapko kahin aur redirect nahi kiya jaata.

10

Best practices - maximum benefit kaise nikaalein

Ye wo aadatein hain jo is resource ko "ek baar padh liya" aur "interview mein yaad aa gaya" ke beech ka farq banati hain.

1. Pehle socho, phir hover karo

Node pe hover karne se pehle 5 second khud socho ki uska answer kya hoga. Active recall se retention kai guna badhta hai. Hover card sirf apne answer ko confirm karne ke liye dekho.

2. Har diagram ke baad quiz, bina exception ke

Diagram padhna comfort deta hai, quiz hi gap dikhata hai. Galat jawab ka explanation zaroor padho - wahi wo jagah hai jahan actual misconception milta hai.

3. Notes ko interview-prep banao

Har note ko aise likho jaise ek hafte baad khud ko samjha rahe ho: "REQUIRED vs REQUIRES_NEW ka farq - outer suspend hota hai, isliye..." Ye notes baad mein ek personal cheat sheet ban jaate hain.

4. Concept chips se sideways jao

Jab bhi passport mein concept chip dikhe, uspe click karo. Ek trap ko teen alag angle se dekhna = wo concept genuinely samajh aana. Iske liye Concepts tab bhi hai.

5. Debug table ko symptom se uthao

Ratna band karo. Jab bhi koi error dikhe, T kholo aur exception ka naam search karo. Cause aur fix dono mil jaate hain. Ye "googling errors" ki aadat ko replace karta hai.

6. Interview bank ko mock banao

Seedha answer mat padho. Question suno, 60 second bolo, phir "Show answer" dabao, phir khud ko score karo. Junior → mid → senior ka order rakho.

7. Book Store ko chala kar dekho

Theory tab tak yaad rehti hai jab tak code nahi chalaya. N+1 endpoint ko khud curl karo, query count khud dekho. Muscle memory banne mein time lagta hai, isliye ye step skip mat karo.

8. Walkthrough ko "proof" ki tarah dekho

Diagram mein likha hai "1 query becomes 18" - walkthrough mein wahi cheez live query count ke saath dikhti hai. Ye do cheezein ek saath dekhne se concept permanent ho jaata hai.

9. Ek track hi khatam karo

Track ke beech se doosre track pe jump karna sabse bada mistake hai. Track ka progress bar 100% tak le jao, uske baad hi agla track kholo.

10. Spaced repetition - 1 hafte baad wapas

Ek track khatam karke 7 din baad dobara kholo aur sirf quiz do. Jo cheezein ab bhi bhool rahe ho, usi pe note update karo. Progress tab se dikh jaayega kahan kamzor ho.

11. Print/PDF le lo

Interview se 2 din pehle poori cheez PDF mein export karke sirf apne notes aur missed quiz questions padho. Screen se zyada effective hai.

12. Concepts ko "ek line mein" bolo

Concepts tab kholo, har concept ko apne shabdon mein ek line mein bolo. Jo na aa sake, wahi dobara padho. Yahi self-test ka sabse tez tareeka hai.

11

30-din ka study plan

Chhe tracks + practice + hands-on ko ek mahine mein fit karne ka suggested sequence. Speed apne hisaab se lo, order mat badlo.

DIN 1-3
Foundations (3 diagrams) Roadmap, container aur startup. Yahan se jo vocabulary milegi (bean, context, lifecycle) wo har jagah kaam aayegi. Din 3 ke end mein quiz 100%.
DIN 4-8
How it works (5 diagrams) Request path, AOP proxy, layers, configuration precedence, auto-configuration. Ye sabse important track hai - yahi interview ka core hai.
DIN 9-13
Data and persistence (4 diagrams) Data model, N+1, Transactions, Caching. N+1 aur Transactions ke walkthrough zaroor chalao - is track ka proof yahi hai.
DIN 14
Security (1 diagram) Security + JWT. Chhota track, lekin filter chain samajh aani chahiye. Debug table ke security entries bhi dekh lo.
DIN 15-18
Running it (4 diagrams) Observability, async/scheduling, messaging (outbox), deployment. Yahan "production mein kya hota hai" wala mindset banta hai.
DIN 19-22
Hardening (4 diagrams) Testing slices, AntiPatterns, migration, roadmap wapas. AntiPatterns ko sabse dhyan se padho - galat cheezein deliberate hain.
DIN 23-25
Book Store hands-on Project chalao, N+1 endpoint curl karo, mode=poison ka 409 khud dekho, transaction probe check karo. C se code lab bhi ek saath khol ke rakho.
DIN 26-27
Quiz sweep - 128 items Practice tab se har diagram ka quiz dobara do. Jo miss ho, usi ka note update karo. Target: har diagram 80%+.
DIN 28-29
Debug table + Interview bank 47 debug entries symptom-wise ek baar padho. Phir 74 interview questions - junior se senior tak, bina answer dekhe.
DIN 30
Revision - notes + PDF Apne saare notes ek baar padho, missed quiz questions dohrao, PDF export karo. Ab tum ready ho.
12

Book Store project - chalane ka tareeka

Diagrams ke saath ek chalne wala Spring Boot 3 application hai jismein wahi deliberate mistakes hain jo diagrams sikhate hain.

  1. Folder kholo: bookstore/ README mein har node id ka mapping hai - kaun sa diagram, kaun sa file. Requirements sirf JDK chahiye.
  2. Test chalao: test.cmd Maven wrapper committed hai, isliye mvn PATH pe na ho tab bhi chalega. Expected: 15 tests, 0 failures.
  3. App start karo: run.cmd Jar build hokar http://localhost:8080 pe chalu ho jaata hai. Health check: /actuator/health.
  4. N+1 ko khud dekho /api/catalog/books/naive vs /api/catalog/books/join-fetch - dono ka payload same, query count alag (18 vs 1).
  5. Transaction modes try karo mode=required → 201, mode=requires-new → 201, mode=poison → 409 rollback. Wahi numbers jo evidence panel mein capture karke rakhe hain.
  6. Diagram ke saath khol ke rakho Ek taraf diagram, doosri taraf terminal. Jaisa diagram bolta hai, wahi terminal mein hota hai - yahi se confidence aata hai.
Project mein jaan-bujhkar rakhi gayi mistakes: self-invocation (advice bypass), N+1 select, rollback-only trap, cache eviction bhool jaana, catch-all exception handler, mutable entities. Inhe "bug" mat samjho - ye teaching material hain. Har ek ke paas uska "fix" bhi pada hai.

14

Advanced - content badalne wale log ke liye

Agar aap sirf padh rahe ho to ye section chhod do. Agar is resource ko apne liye customize karna hai, to yahi se shuru karo.

Sab kuch tools/ se banta hai

build-content-index.mjs (index) → build-code-viewer.mjs (code mirror) → enhance-hover.mjs (diagram tags). Order matter karta hai.

Evidence dobara capture karna ho

capture-evidence.mjs app khud start karta hai, port 8080 pe jo bhi purana process hai use pehle band karta hai, responses assert karta hai, aur band hone par confirm karta hai. Uske baad build-traces.mjs chalana zaroori hai.

Validation commands

audit-links, probe-code-viewer, probe-code-lab, probe-hover, probe-kit, probe-hub - sab node tools/<name>.mjs se chalte hain.

Naya diagram kaise add karein

Pehle HTML banao, phir content-index.js rebuild karo, phir enhance-hover.mjs chalao. Audit khud check kar lega ki har node id, edge aur code link sahi hai.

Mat haath se badlo: evidence.js, code-source.js, content-index.js aur base diagrams ko manually edit mat karna - ye generated hain aur agli run par overwrite ho jaayenge.
